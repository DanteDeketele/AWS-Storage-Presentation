BasisDrie soorten storage

Block

Ruwe schijf, opgedeeld in blokken

File

Mappen en bestanden, gedeeld

Object

Key → object + metadata

AWS heeft drie grote soorten storage. Klik op elke kaart.

  • Block: een ruwe schijf. Het OS zet er zelf een filesystem op. Snelst, voor databases en boot-schijven.
  • File: mappen en bestanden, gedeeld via NFS of SMB. Meerdere servers tegelijk.
  • Object: key + data + metadata in een bucket, via HTTPS. Goedkoop en onbeperkt schaalbaar.

Vuistregel: één server, snel → block · delen → file · veel data, goedkoop → object.

Het belangrijkste verschil zit in de rij Wijzigen: bij block wordt enkel het gewijzigde blok herschreven, bij object het hele object. Daarom is block het snelst voor databases.

Block hangt meestal aan één server; daarvoor heb je file storage als je wil delen.

Eigen schemaAmazon EBS in één beeld

Dit is ons eigen schema. Klik de stappen één voor één.

  1. Volume in één AZ. Een EBS-volume is een netwerkschijf, geen schijf in de server. Het leeft in één Availability Zone, hier eu-central-1a, en kan enkel aan een EC2-instance in diezelfde AZ. Binnen die AZ wordt het automatisch gerepliceerd. Root en data zijn allebei EBS-volumes.
  2. Instance store. Het rode blok zit wél fysiek in de host. Supersnel, maar tijdelijk: weg bij stop of terminate. Komt straks nog terug.
  3. Snapshot. Wil je het volume beschermen of verplaatsen, dan neem je een snapshot. Die staat in S3 en is regionaal: niet meer aan één AZ gebonden. Incrementeel: enkel gewijzigde blokken.
  4. Andere AZ. Uit die snapshot maak je een nieuw volume in een andere AZ, of je kopieert hem naar een andere regio. Zo verhuis je een EBS-volume.

Kernboodschap: volume = één AZ, snapshot = hele regio.

Waarom gp3?Reken zelf: gp2 vs gp3

gp2 geeft 3 IOPS per GiB → voor meer IOPS moet je meer GB kopen.
gp3 geeft 3.000 IOPS inbegrepen; extra IOPS koop je los (max. 500 IOPS per GiB).

gp2

gp3

Live voorbeeld: een database van 100 GB die 3.000 IOPS nodig heeft.

Bij gp2 krijg je 3 IOPS per GiB, dus moet je 1.000 GB kopen: $119 per maand.

Bij gp3 zijn 3.000 IOPS inbegrepen: 100 GB is genoeg, $9,52 per maand.

Schuif de IOPS omhoog: gp3 blijft goedkoper. Let op: gp3 heeft max. 500 IOPS per GiB.

FeaturesSnapshots en encryptie

Snapshots

  • Point-in-time back-up in S3 (geen zichtbare bucket)
  • Incrementeel: enkel gewijzigde blokken
  • Tussenliggende snapshot verwijderen is veilig
  • Regionaal → nieuw volume in elke AZ
  • $0,054/GB-maand · archive $0,0135

Encryptie met AWS KMS

  • AES-256 met een data key uit KMS
  • At rest, in transit EC2 ↔ volume, en snapshots
  • Encryption by default: instelling per regio
  • Bestaand volume: snapshot → versleuteld volume
  • Howest-account: een SCP blokkeert kms:Encrypt → de demo-volumes zijn niet versleuteld

Snapshots: de eerste kopieert alle gebruikte blokken, de volgende enkel wat veranderde. Een tussenliggende verwijderen is veilig. Snapshots zijn regionaal.

Encryptie: EBS vraagt een data key aan KMS en versleutelt met AES-256 in de Nitro-hardware. Data at rest, het verkeer naar de instance en de snapshots zijn dan versleuteld.

Een bestaand volume kun je niet zomaar versleutelen: via een snapshot maak je een versleutelde kopie.

Bij Howest blokkeert een SCP KMS. Daarom zijn onze demo-volumes onversleuteld.

Met Elastic Volumes vergroot je een volume terwijl het in gebruik is. Twee lagen:

  1. AWS maakt de schijf groter (modify-volume). Bij "optimizing" is de ruimte al bruikbaar.
  2. Het OS ziet dat nog niet: je breidt partitie en filesystem uit.

Verkleinen kan niet. Max. 4 wijzigingen per 24 uur, en de vorige moet "completed" zijn.

Dat doen we straks live.

Instance store

  • NVMe in de host: zeer snel, inbegrepen in de prijs (m5d, i3)
  • Weg bij stop, hibernate, terminate, defect, type wijzigen
  • Blijft bij een reboot
  • Voor cache, buffers, scratch of data die elders gerepliceerd is

Gebruik de simulator: klik Reboot (alles blijft), dan Stop (instance store is weg).

Instance store is fysiek in de host. Bij een stop start je instance op een andere host, dus de oude schijf is weg. Ook bij hibernate, terminate of een defect.

Goed voor cache en tijdelijke data, nooit voor iets dat je wil houden.
